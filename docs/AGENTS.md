# Агенты: команда студии и их инструкции

Промпт агента — **документ Markdown**, а не строка в Python. Файл
читается человеком (видно, что именно инструктирует модель), диффится
в ревью построчно, версионируется в git и правится без правки кода.

## Формат `agents/<name>.<execution>.md`

```markdown
---
name: project-qa              # обязательное
execution: api                # обязательное: api | cli
description: ...              # обязательное: одна строка для списков
tools: [corpus, rag, citations]   # необязательное, только метаданные
temperature: 0.2              # необязательное, по умолчанию 0.2
---
Тело — это и есть системный промпт: правила, тон, формат ответа.
```

* Разбор — `studio/backend/agents.py :: parse_frontmatter` (без YAML-
  пакета: `ключ: значение`, inline-список `[a, b]`, числа/строки).
* Загрузка — `AgentRegistry`: кэш по mtime каталога и файлов, правка md
  подхватывается **без перезапуска** процесса; битый файл не роняет
  реестр, а попадает в `errors()` и виден в CLI/API.
* `tools` и `temperature` — описание агента. Температура вызова сейчас
  фиксирована в `assistant.py :: _llm` (0.2), а температура agent-файлов
  — в `agents.py` по фронтматтеру; `tools` в промпт не подставляется.

## Команда: 4 агента × 2 исполнения = 8 файлов

Один и тот же агент для веба (`.api.md`) и для терминала (`.cli.md`):
различается канал, а не назначение — в вебе ответ рендерится в узкой
панели рядом с источниками, в терминале — печатается и часто уходит в
пайп (`> faq.md`, CI-логи).

| Агент | Для чего нужен | Инструменты (метаданные) | Где используется |
|---|---|---|---|
| `project-qa` | Отвечает на вопросы о проекте: модули, архитектура, пайплайн, назначение агентов. Отвечает **только по фрагментам корпуса**; нет ответа — так и говорит | `corpus, rag, citations` | веб: вкладка «Ассистент», `POST /api/assistant/ask`; CLI: `cli.py ask` |
| `code-review` | По **уже найденным** детерминированным находкам (правило, severity, файл, строка) формулирует ≤5 связных рекомендаций. Новые проблемы и номера строк выдумывать запрещено | `git, diff, corpus` | веб: блок «Ревью», `POST /api/assistant/review`; CLI: `cli.py review` |
| `support` | Ответ пользователю по тикету с персонализацией из CRM: план и оплата меняют тон и шаги, роль — глубину, история — повторные шаги. Фактов о продукте не выдумывает | `crm, tickets, corpus` | веб: блок «Поддержка», `POST /api/assistant/support`; CLI: `cli.py support` |
| `file-ops` | Автономные файловые операции по цели: поиск использований, обновление документации, генерация ADR/changelog/README, проверка инвариантов, отчёт по diff. Запись — только в allow-list, git только на чтение | `corpus, git, fs-write-allowlist` | веб: блок «Сценарии»; CLI: `cli.py scenario` |

### Чем `.api.md` отличается от `.cli.md`

| | `.api.md` | `.cli.md` |
|---|---|---|
| Канал | веб-панель | терминал, пайпы, CI-логи |
| Ссылки на файлы | по именам (рядом панель источников) | `путь:строка` прямо в тексте |
| Формат | умеренная структура, без HTML | markdown, короткие строки (≤ ~100 симв.), языки в блоках кода |
| Ограничение | — | не ссылаться на элементы UI («нажмите», «панель справа») |

## Как промпт попадает в вызов (без хардкода)

```
agents/project-qa.api.md ──AgentRegistry.prompt_for("project-qa", "api")──▶
   assistant.py :: agent_prompt("project-qa") ─▶ ask_project / review_diff / support_answer
                                                 └─▶ _llm(system=промпт, user=контекст)
```

* Веб: `assistant.py :: ask_project` / `review_diff` / `support_answer`
  берут промпт через `agent_prompt(...)` → `agents/<name>.api.md`.
* CLI: `cli.py :: _agent_prompt` → `agents/<name>.cli.md`; опция
  `--agent <name>` позволяет указать агента другой команды.
* Если файла нет или frontmatter битый — запрос не падает: сервис
  деградирует на детерминированный ответ (`llm=false`), а причина
  доступна в `GET /api/assistant/agents` → `errors`, в
  `cli.py agents list` и в поле `llm_error` ответа.
* В `assistant.py` **нет** встроенных системных промптов: удалённые
  `_ASK_SYSTEM` / `_REVIEW_SYSTEM` / `_SUPPORT_SYSTEM` заменены
  реестром. Проверка — `tests/test_agents.py` и
  `studio/backend/tests/test_agents.py`.

## Автономный CLI-ассистент `dev_assistant.py`

У него свой промпт — `SYSTEM_PROMPT` в `dev_assistant.py`: это
отдельный инструмент вне сервиса `AssistantService` (свой поиск, свой
индекс, работа без студии). Он не входит в команду `agents/*.md`.

## Как править и проверять

```bash
# из корня репозитория
PY=.venv/bin/python

# 1. Список агентов: имя, исполнение, файл, ошибки разбора
$PY studio/backend/cli.py agents list

# 2. Карточка и полный промпт — то, что уйдёт в модель
$PY studio/backend/cli.py agents show project-qa --execution cli --prompt
$PY studio/backend/cli.py agents show support --execution api

# 3. Померить влияние правки: ответ до / после
$PY studio/backend/cli.py ask "для чего нужен агент file-ops?"

# 4. Тесты формата и загрузки
$PY -m pytest studio/backend/tests/test_agents.py tests/test_day31_cli.py -q
```

Правка промпта = правка `.md`; перезапуск сервера не нужен (кэш
инвалидируется по mtime), но уже запущенная команда использует
загруженный ранее текст.

## Ограничения

* `tools` в frontmatter — метаданные для людей и API, а не маршрутизация
  инструментов: доступные сервису инструменты заданы в коде
  (`assistant.py`, `agent.py`).
* `temperature` из md пока не применяется в веб-вызове (0.2 в `_llm`);
  CLI передаёт своё значение явно.
* Агенты не коммитят и не пушат: решение о коммите остаётся за
  человеком.
