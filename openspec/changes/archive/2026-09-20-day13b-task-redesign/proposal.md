# Proposal: day13b-task-redesign

## Why

День 13 (Task State Machine) реализован и проверен, но ручная проверка
показала отрыв от замысла задания: задача запускалась через отдельную
вкладку «Задача», оторванную от диалога, спавн и работу stage-агентов в
диалоге не было видно, а выводы стадий нельзя было разбирать как
процесс. Фидбек пользователя: задача = запрос пользователя в любом
диалоге; спавн агентов и их работа видны в диалоге в сворачиваемой
карточке процесса; вкладка «Задача» убирается; добавляется тумблер
режимов чат/задача.

Ветка: `day13-task-state-machine` (продолжение дня 13).

## What Changes

- **BREAKING (UI)**: убирается вкладка «Задача» в панели «Контекст»
  (`TaskTab.tsx`), кнопка Стоп в шапке чата и статус-строка стадий;
  stage-выводы перестают быть отдельными сообщениями чата с чипом
  «задача».
- **Задача = запрос пользователя**: в режиме «задача» сообщение поля
  ввода чата запускает задачу (форма запуска убрана); на паузе поле
  ввода = instruction. Тумблер режимов «чат»/«задача» (глобальный,
  персистентный, заблокирован во время работы непаузанной задачи).
- **Схема состояния задачи** (unified FSM): `stage`
  `planning|execution|validation|done|paused|failed` (пауза и ошибка —
  значения стадии, не флаги), `task_id` (новый на каждую задачу),
  `current_step`/`total_steps`, `expected_action`
  (`agent_response|human_input|resume_wait`), `plan` (агенты-стадии со
  статусами и timestamps спавна), `work_steps` (шаги декомпозиции
  Планировщика), `context_snapshot` (данные для продолжения без
  повторных объяснений).
- **Пошаговое исполнение**: Планировщик возвращает структурированный
  план (work-шаги, best-effort JSON, фолбэк — план из 1 шага);
  Исполнитель исполняет шаги по одному (отдельный LLM-вызов на шаг,
  статус `pending→in_progress→completed`, вывод шага), поток вывода
  текущего шага стримится в реальном времени.
- **Карточка процесса в потоке чата**: после сообщения-запроса —
  карточка: заголовок (описание, статус-бейдж, кнопки
  Пауза/Продолжить/Повтор), прогресс-бар (шаг N/4 + «Этап N/4:
  <label>»), секции агентов со сворачиванием/разворачиванием (иконка,
  имя, бейдж статуса, «спавн X с назад»; Исполнитель — чек-лист
  work-шагов + живой бокс вывода). Спавн агента виден; на `done` —
  секции свёрнуты; на `failed` — секция ошибки развёрнута + «Повтор»;
  после перезагрузки — восстановление из маркеров сообщений.
- **SSE-события**: `stage`/`stage_done` заменяются на `agent_spawned`,
  `step_updated`, `step_delta`, `stage_done`, `task_paused`,
  `task_resumed`, `task_done`, `task_failed`, `error`.
- **API**: `start` на завершённой (`done`)/упавшей (`failed`) задаче =
  новая задача (новый `task_id`); `run` на `failed` = повтор с упавшей
  стадии/шага; гард `/api/chat` не меняется.
- **Передача контекста формализована**: system-промпты stage-агентов
  собираются только из состояния задачи (`context_snapshot`:
  описание, work-шаги с выводами, instruction); история чата в
  task-промпты не уходит (чат — лишь представление процесса для
  пользователя).
- **Архитектура**: расширение существующего hand-rolled оркестратора
  (без LangGraph/Temporal: 0 новых зависимостей, одно JSON-хранилище,
  модель состояния совместима с будущим переносом — см. design.md).

### Modified Capabilities

- `task-state-machine`: схема состояния задачи (unified stage,
  `task_id`, `plan`/`work_steps`, `expected_action`, `context_snapshot`),
  пошаговое исполнение, пауза на границе work-шага, новые SSE-события,
  задача = запрос пользователя в режиме «задача», карточка процесса и
  тумблер режимов вместо вкладки «Задача».

## Impact

- **Код (бэкенд)**: `studio/backend/memory.py` (схема и методы
  task-состояния), `studio/backend/agent.py` (`task_run`: пошаговый
  цикл, структурированный планировщик, стриминг `step_delta`, новые
  события, paused/failed как стадии), `studio/backend/main.py`
  (семантика `start`/`run`).
- **Код (фронтенд)**: новый `components/TaskCard.tsx`;
  `ChatPanel.tsx` (карточка, тумблер режимов, семантика поля ввода,
  удаление кнопки Стоп), `ContextPanel.tsx` (удаление 5-й вкладки),
  `TaskTab.tsx` (удаляется), `state.tsx`/`api.ts` (новые события,
  тумблер).
- **Данные**: поле `task` в `dialogues.json` — новая схема (dev-данные,
  миграция не требуется; код обрабатывает отсутствие/старые поля).
- **Зависимости**: новых нет (LangGraph/Temporal рассмотрены и
  отклонены — design.md, Decisions).
