## Purpose

Самостоятельное приложение дня 11 «Студия»: веб-чат с LLM (GPustack,
OpenAI-совместимый API) на FastAPI + React (Vite/TS), трёхслойная память
(«Диалог» / «Текущая задача» / «Долговременная») с ручным управлением
человеком и наблюдаемой инъекцией в system-промпт, Token HUD, аннотированный
журнал API-запросов с пояснением каждого параметра и fallback-пометкой для
неизвестных, JSON-хранилище, mid-dark UI раскладки «Студия».

## ADDED Requirements

### Requirement: Три слоя памяти с ручным управлением

Система SHALL хранить три слоя памяти в трёх отдельных хранилищах
(JSON-файлах): «Диалог» (Short-Term Memory) — сообщения диалогов; «Текущая
задача» (Working Memory) — key/value, пер-диалоговая; «Долговременная»
(Long-Term Memory) — key/value, глобальная (все диалоги). Управление
исключительно ручное, явными действиями пользователя (добавить key/value,
удалить key, clear слоя); авто-извлечения и routing-правил НЕ должно быть.
Все слои MUST переживать перезапуск сервера. Данные одного слоя MUST NOT
смешиваться с хранилищами других слоёв.

#### Scenario: Долговременная переживает рестарт и смену диалогов

- **WHEN** в «Долговременную» сохранено key/value, сервер перезапущен, открыт новый диалог
- **THEN** значение присутствует в «Долговременной» и доступно (в инъекции) в новом диалоге

#### Scenario: «Текущая задача» пер-диалоговая

- **WHEN** в «Текущей задаче» диалога A сохранён key и активирован диалог B
- **THEN** key виден при активном диалоге A, но НЕ инъектируется в контекст диалога B

#### Scenario: Слои лежат в разных файлах

- **WHEN** сохранены значения в «Текущую задачу» и «Долговременную»
- **THEN** каждое значение находится только в файле своего слоя

#### Scenario: Ручной CRUD без LLM

- **WHEN** пользователь добавляет, удаляет или очищает записи слоя
- **THEN** изменения применяются без каких-либо LLM-вызовов и видны в GET /api/memory

### Requirement: Инъекция памяти в system-промпт

Система SHALL добавлять в system-промпт непустые блоки: «Текущая задача»
активного диалога (строки «- key: value») и «Долговременная» (строки
«- key: value»). Пустой слой MUST не добавлять блока (system-промпт не
мечается). Сообщения диалога (ST) в system-промпт не дублируются — они идут
в `messages` payload.

#### Scenario: Непустые слои в промпте

- **WHEN** в «Текущей задаче» активного диалога и в «Долговременной» есть значения
- **THEN** system-промпт в LLM-запросе содержит оба блока со строками значений

#### Scenario: Пустые слои не меняют промпт

- **WHEN** оба слоя пусты
- **THEN** system-промпт совпадает с базовым (из конфига), блоков памяти нет

### Requirement: Чат с LLM через FastAPI с SSE-стримингом

Система SHALL предоставлять POST `/api/chat` (`{"dialogue_id", "message"}`),
отвечающий SSE-стримом: события `delta` (фрагменты ответа), `done`
(полный ответ + usage + request_id), `error` (RU-сообщение). LLM-запрос —
OpenAI-совместимый `/chat/completions` GPustack c `stream: true`
(параметры: model, temperature, max_tokens — из конфига). Сбой API MUST
приводить к событию `error`, а не к молчанию.

#### Scenario: Стрим доходит до done

- **WHEN** клиент шлёт сообщение и GPustack доступен
- **THEN** клиент получает один или более `delta` и завершающее `done` с usage; ответ сохраняется в диалоге

#### Scenario: Сбой API — событие error

- **WHEN** GPustack недоступен/вернул ошибку
- **THEN** стрим содержит `error` с RU-сообщением; диалог не повреждён

### Requirement: Диалоги

Система SHALL поддерживать диалоги: создание (новый становится активным),
список, чтение сообщений, переключение активного, удаление (с удалением его
«Текущей задачи»). Активный диалог определяется на сервере.

#### Scenario: Новый диалог

- **WHEN** POST /api/dialogues
- **THEN** создан диалог, он стал активным, список обновлён

#### Scenario: Удаление диалога

- **WHEN** DELETE /api/dialogues/{id}
- **THEN** диалог и его «Текущая задача» удалены; если удалён активный — активным становится другой диалог (или пустой список)

### Requirement: UI раскладки «Студия» (mid-dark)

Фронтенд SHALL быть React-приложением с раскладкой из трёх панелей: слева —
диалоги + сводка памяти (счётчики слоёв), в центре — чат (лента сообщений,
стриминг ответа, инпут), справа — панель «Контекст» с вкладками «Память» /
«Токены» / «Запрос». Тема — mid-dark (фон #1e1e24, панели #26262e, границы
#3a3a44), чистый CSS с дизайн-токенами. Имена слоёв на UI — «Диалог» /
«Текущая задача» / «Долговременная»; при наведении (title) SHALL
показываться английское обозначение (Short-Term Memory / Working Memory /
Long-Term Memory).

#### Scenario: Три панели и вкладки

- **WHEN** открыто приложение
- **THEN** видны три панели и в правой панели — вкладки «Память», «Токены», «Запрос»

#### Scenario: Английское обозначение на hover

- **WHEN** курсор наведён на имя слоя в UI
- **THEN** показывается английское обозначение слоя (Short-Term / Working / Long-Term Memory)

#### Scenario: Управление памятью из UI

- **WHEN** пользователь в правой панели добавляет key/value в «Текущую задачу» или «Долговременную», удаляет key или нажимает clear
- **THEN** слой и сводка в левой панели обновляются без перезагрузки страницы

### Requirement: Token HUD

Система SHALL показывать токен-статистику: prompt / reasoning / total
последнего запроса (точные значения из API usage) и лимит контекста модели;
вкладка «Токены» — развёрнутая статистика (оценка размера слоёв, кумулятив за
сессию). Оценки слоёв — эвристика (задокументирована) и помечаются как
оценки; значения из API usage — точные.

#### Scenario: HUD после запроса

- **WHEN** выполнен chat-запрос
- **THEN** HUD показывает prompt/reasoning/total из usage и лимит выбранной модели

#### Scenario: Развёрнутая статистика

- **WHEN** открыта вкладка «Токены»
- **THEN** видны оценка токенов по слоям памяти и кумулятивные итоги за сессию

### Requirement: Аннотированный журнал запросов

Вкладка «Запрос» SHALL иметь toggle «показывать/скрыть». При включённом
показе: последний запрос отображается параметрами вида «имя = значение —
пояснение», где пояснение берётся из словаря (отдельный расширяемый файл
фронтенда, покрывающий стандарт OpenAI-совместимого API и usage-поля);
usage-блоки (prompt_tokens / completion_tokens / total_tokens) — с
пояснениями. Параметр, отсутствующий в словаре, MUST отображаться со
значением и пометкой «(доп. параметр, без описания)» (серым, визуально
отличным). Журнал SHALL хранить последние запросы с timestamp; каждый
запрос раскрывается (полное тело по id).

#### Scenario: Параметр из словаря

- **WHEN** в запросе есть параметр `temperature`
- **THEN** он отображается со значением и RU-пояснением из словаря

#### Scenario: Неизвестный параметр

- **WHEN** в запросе есть параметр, отсутствующий в словаре (например, вендорское поле)
- **THEN** он отображается со значением и пометкой «(доп. параметр, без описания)», ничего не скрывается

#### Scenario: Toggle показывает/скрывает

- **WHEN** пользователь переключает toggle «показывать запросы»
- **THEN** журнал/аннотации скрываются и вновь появляются; состояние переживает перезагрузку страницы

#### Scenario: Журнал и раскрытие

- **WHEN** выполнено несколько chat-запросов
- **THEN** журнал содержит записи с timestamp; клик по записи открывает полное тело запроса

### Requirement: Хранилище и атомарность

Данные (диалоги, «Текущая задача», «Долговременная», журнал запросов) SHALL
храниться в JSON-файлах `studio/data/` с атомарной записью (tmp + replace),
UTF-8, `ensure_ascii=False`. Повреждённый/отсутствующий файл MUST
приводить к дефолтным значениям (приложение стартует, данные слоя пусты),
а не к падению. Файлы данных и `.env` MUST быть в `.gitignore`.

#### Scenario: Битый файл — дефолты

- **WHEN** файл слоя содержит не-JSON
- **THEN** приложение стартует, слой считается пустым, дальнейшие записи работают

#### Scenario: Персистентность

- **WHEN** выполнены операции с памятью/диалогами/журналом и сервер перезапущен
- **THEN** все данные сохранены (кроме сессионного кумулятива токенов — оценка за сессию)

### Requirement: Проверка (тесты, e2e, README)

Репозиторий SHALL содержать: pytest-тесты бэкенда (офлайн, fake LLM-транспорт:
память, инъекция, API-валидации, SSE-поток), Vitest smoke-тесты фронтенда
(покрытие словаря + fallback, состояние, рендер unknown-параметра),
`scripts/e2e_studio.py` (поднимает сервер, проходит HTTP-поток включая
SSE-чат, память, токены, журнал, UI; chat-шаг SKIP при недоступном GPustack;
exit 0 = PASS/SKIP, 1 = FAIL) и секцию «День 11 (студия)» в README
(структура, запуск dev/prod, API, память, токены, запросы/glossary, тесты).

#### Scenario: Офлайн-прогон тестов

- **WHEN** запущены `pytest` и `vitest run` без доступа к GPustack
- **THEN** все тесты проходят (LLM подменён фейком)

#### Scenario: E2E

- **WHEN** запущен `python scripts/e2e_studio.py`
- **THEN** пройден HTTP-поток (config, диалог, chat-SSE, память, токены, журнал, UI), при недоступном API chat-шаг SKIP, exit 0
