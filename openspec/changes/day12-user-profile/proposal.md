# Proposal: day12-user-profile

## Why

День 12: персонализация ассистента поверх модели памяти дня 11 (студия).
Сегодня студия single-tenant: ответов «под пользователя» нет — агент не знает,
кому говорит, как с ним общаться и чего избегать. Задание: создать профиль
пользователя, описать предпочтения (стиль, формат, ограничения) и подключить
профиль к каждому запросу — чтобы один и тот же вопрос в разных диалогах с
разными профилями давал разные ответы.

Ветка: `day12-user-profile` от `day11-studio`.

## What Changes

- **Профиль пользователя per-диалог**: 4 поля (имя, профессиональная роль и
  сфера, тон и стиль общения, стоп-слова/табу) + статус. Профиль хранится в
  записи диалога (`dialogues.json`) и переживает перезапуск сервера;
  переключение диалогов переключает профиль.
- **Инициализация при первом запросе**: в новом диалоге без профиля агент на
  первый ход не отвечает по существу, а предлагает инициализацию: заполнить
  вручную / провести интервью / отказаться.
  - **Интервью** — агент одним сообщением задаёт 4 вопроса, из ответа
    пользователя LLM (нестриминговый best-effort вызов, паттерн авто-заголовка)
    извлекает структурированный профиль.
  - **Вручную** — пользователь заполняет форму в новой вкладке «Профили».
  - **Отказ** — статус `declined`; запросы выполняются как обычно, в UI —
    постоянный бейдж «профиль не заполнен — после инициализации ответы точнее»
    с возвратом к инициализации по клику.
- **Инъекция в каждый запрос**: `active`-профиль добавляется блоком в
  system-промпт в `build_payload` (вместе со строкой «избегай» при
  непустых стоп-словах). Тело `/api/chat` не меняется — профиль подключается
  автоматически по `dialogue_id`.
- **API**: профиль включается в ответ выдачи диалога; новые эндпоинты
  `POST /api/profile` (ручное сохранение полей), `POST /api/profile/action`
  (`interview` | `decline` | `reset`).
- **Фронтенд**: вкладка «Профили» в панели «Контекст» (форма 4 полей, кнопки
  Интервью / Заполнить заново / Отказаться, состояние активного диалога),
  бейдж в шапке чата при `declined`/`pending`.
- **Проверка**: два диалога с разными профилями → разные ответы на один
  вопрос; инъекция видна в `GET /api/rules` и в JSON запроса; pytest
  (бэкенд, fake-LLM), Vitest (фронт), расширение `scripts/e2e_studio.py`.

## Capabilities

### New Capabilities

- `user-profile`: персонализация студия — профиль пользователя per-диалог
  (имя/роль/тон/стоп-слова) с инициализацией через интервью или вручную,
  статусами (pending/active/declined), инъекцией в system-промпт каждого
  запроса, REST API, вкладкой «Профили» и бейджем напоминания в UI.

## Impact

- **Код**: `studio/backend/memory.py` (profile-методы `MemoryStore`),
  `studio/backend/agent.py` (`build_payload`, state machine инициализации,
  LLM-экстракт профиля), `studio/backend/main.py` (эндпоинты профиля);
  фронтенд: новый `components/ProfileTab.tsx`, правки `ChatPanel.tsx`
  (бейдж), `ContextPanel.tsx` (таб), `state.tsx`, `api.ts`.
- **Данные**: `dialogues.json` — новое поле `profile` в записи диалога
  (бэкворд-совместимо: отсутствие поля = `pending`); новые файлы не
  появляются.
- **Совместимость**: body `/api/chat` и существующие `/api/memory/*`
  эндпоинты не меняются; слои памяти и конфликт-гард WM/LT не трогаются —
  профиль это предпочтения, не факты памяти.
