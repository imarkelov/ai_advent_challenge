# Design: day28-local-rag

## Контекст

День 28 требует RAG-систему, **полностью работающую локально в Ollama**:
индекс из Недели 6, retrieval локально, генерация — локальной моделью.
К дню 28 в репозитории уже есть:

| Часть | Где | Состояние |
|---|---|---|
| Индекс (chunks + векторы + terms, `index.db`) | `kb.py` (день 21) | готов, формат version 1 |
| Гибридный поиск (вектор + BM25, RRF) | `kb.py::search` | готов |
| Двухэтапный RAG (recall + реранкер + `min_score`) | `kb.py::search_rag` (дни 21/23) | готов |
| RAG-чат (kb_block, `rag_context`, `CITE_RULE`, dont-know) | `agent.py` (дни 21/24) | готов |
| **Локальная генерация** | `agent.py` (день 26): `LOCAL_MODELS`, `_base_for`, `list_models` | готов |
| Эмбеддеры | `kb.py`: `hash` (офлайн, слабая семантика), `api` (GPustack, сеть+ключ) | **нет локального семантического** |

Разрыв — ровно в эмбеддере. `hash` локален, но 256-мерный char-3-gram
md5 не различает смысл («ксилофон» и «музыкальный инструмент» далеки);
`api` семантичен, но требует GPustack и ключ. Локальная генерация дня 26
без локального эмбеддера вынуждена либо работать без RAG, либо ходить
в сеть за векторами.

## Решение

Добавить **третий эмбеддер `ollama`** — не замену, а соседа
существующих, в том же контракте.

### 1. `OllamaEmbedder` — по образцу `APIEmbedder`

`APIEmbedder` (день 21) уже реализует нужный протокол:
`POST {base}/embeddings {"model", "input": batch}`, батчи по 16, `dim`
с первого ответа, сортировка `data[]` по `index`, `KBError` при сбое,
`client` DI для `MockTransport`-тестов. Ollama отдаёт
OpenAI-совместимый `/v1/embeddings` (проверено: `nomic-embed-text:v1.5`
→ 768 dim), поэтому класс — почти копия с тремя отличиями:

1. `name = "ollama"`, `model = EMBED_MODEL_LOCAL`;
2. `api_key` по умолчанию `"ollama"` — заглушка (Ollama не проверяет
   `Authorization`, но клиент всегда шлёт заголовок);
3. сообщения `KBError` называют Ollama и `base_url` — при недоступном
   сервисе в логе/502 сразу видно, что дело в локальной модели.

Копия, а не наследование от `APIEmbedder`: классы отличаются и
семантикой (локальный vs сетевой провайдер), и точками роста
(например, у Ollama есть нативный `/api/embeddings`). Общий рефакторинг
в базовый класс затронул бы `api`-путь дней 21–25 — вне задачи дня 28.

### 2. Модель для retrieval — из индекса, не из env

`_embedder_from_index` получает весь `idx` и для `ollama` вызывает
`ollama_embedder_from_env(model=idx.get("model"))`. Это критично:

- векторная нога считает `cosine(qv, chunk_vector)`; если запрос
  посчитать другой моделью (или другой размерности), косинус
  бессмыслен — поиск деградирует молча, без ошибки;
- `OLLAMA_EMBED_MODEL` в env описывает модель для **новой сборки**;
  поиск по уже собранному индексу обязан следовать индексу.

`model` в meta писался днями 21–25 (`hash` → `null`), поэтому формат
`index.db` не меняется и миграция не нужна.

### 3. Безопасная деградация: 502, а не тихий фолбэк

`kb.build` при сбое эмбеддера пробрасывает `KBError` → роут отдаёт
502. Соблазн «упасть на `hash`» отвергнут: индекс получил бы векторы
иной размерности, а `embedder`/`dim` в meta разошлись бы с реальностью
— молчаливо сломанный RAG хуже явной ошибки. Существующий
лексический (BM25) фолбэк в `search` остаётся: он включается, когда
векторная нога недоступна **при поиске**, а `terms` в индексе есть
(индексы дней 21–25 их всегда пишут).

### 4. Смена эмбеддера = полная пересборка

Правило дня 21 (`mode: "auto"` → incremental только при совпадении
strategy+embedder) распространяется на `ollama` без правок: векторы
768-мерного `nomic-embed-text` и 8b-`qwen3-vl-embedding` несравнимы,
инкремент запрещён. `update_settings` дополняется значением `ollama`,
чтобы настройка не расходилась с возможностями сборки.

### 5. UI: третий вариант + фактическая модель

`KbStats` теперь несёт `model` (аддитивно) — строка «Модель» в
статистике показывает, чем реально построен индекс (`hash` → строки
нет). Тип на фронтенде опциональный (`model?: string | null`):
старый/чужой бэкенд без поля рендерится без строки, без краха.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Заменить `hash` на `ollama` | Ломает офлайн-тесты и индексы дней 21–25; `hash` — детерминированный фолбэк без зависимостей |
| Заменить `api` на `ollama` | Пользователь может предпочитать 8b-качество; день 28 добавляет возможность, а не отнимает |
| Нативный `/api/embeddings` Ollama | OpenAI-совместимый `/v1/embeddings` уже поддержан `APIEmbedder`-паттерном; нативный API — лишняя ветка кода без выгоды |
| Брать модель из `OLLAMA_EMBED_MODEL` при поиске | Расхождение с индексом при смене env → бессмысленный косинус, молчаливая деградация |
| Фолбэк на `hash` при недоступной Ollama | Индекс с несравнимыми векторами; явная 502-ошибка честнее |
| Общий базовый класс для `APIEmbedder`/`OllamaEmbedder` | Рефакторинг `api`-пути дней 21–25 вне scope дня 28 |

## Проверка

- **Юнит (офлайн, `MockTransport`)**: 15 тестов `OllamaEmbedder` +
  диспетчер `_embedder_from_index` в `test_kb.py`; 6 тестов роутов
  (`ollama`-сборка, отсутствие ключей, `model` в stats, локальный
  поиск, настройки) в `test_kb_api.py`.
- **E2E**: `scripts/e2e_day28.py`, Part A офлайн (MUST PASS) + Part B
  live на Ollama (best-effort, SKIP без Ollama).
- **Локальность**: перехват `httpx.Client.send` показывает, что все
  запросы пайплайна уходят только на `localhost:11434`; при пустых
  `GPUSTACK_*` сетевого пути нет вовсе.
- **Регрессия**: полный `pytest -m "not live"` зелёный; `hash`/`api`
  индексы и `e2e_day21`–`e2e_day25` не затронуты.
