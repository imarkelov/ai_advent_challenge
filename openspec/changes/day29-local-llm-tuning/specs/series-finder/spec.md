# Spec: series-finder

## Назначение

Оптимизация локальной LLM под задачу «поиск новых сериалов»: профили
параметров инференса, промпт-шаблон под кейс, замер квантования и
измеримое качество рекомендаций по реальному каталогу.

## Термины

* **Профиль** (`TaskProfile`) — именованный набор параметров
  инференса (`model`, `temperature`, `top_p`, `num_predict`, `num_ctx`,
  `seed`) и `system_prompt`, оптимизированный под задачу.
* **Каталог** — реальные сериалы из Wikidata
  (`data/series/catalog.json`), нормализованные: `id`, `imdb`,
  `title`, `year`, `genres`, `country`, `countries`, `languages`,
  `seasons`, `episodes`.
* **Кандидаты** — подмножество каталога, поданное модели в промпте
  (пронумеровано 1..K; номер = `id` в ответе).
* **Верность каталогу** — доля рекомендованных `id`, найденных в
  предложенном каталоге (антигаллюцинация).

## Функциональные требования

### FR-1 Профили оптимизации

* FR-1.1 Система предоставляет ≥ 4 профиля: `studio` (дефолт),
  `series` (кейс дня), `series_q8` (замер квантования),
  `series_json` (строгий JSON).
* FR-1.2 Профиль `studio` НЕ задаёт `num_ctx` (поведение до дня 29:
  запрос уходит без `num_ctx`) и использует `temperature=0.7`,
  `max_tokens=2048` — значения, идентичные `DEFAULT_CONFIG` дней 11–28.
* FR-1.3 Профиль `series` задаёт `temperature=0.2`,
  `num_predict=512`, `num_ctx=8192`, `seed=29`.
* FR-1.4 Профиль иммутабелен (`frozen`): параметры нельзя изменить
  после создания; копия — `with_overrides`.
* FR-1.5 `profile_for(None|неизвестный)` возвращает `studio`
  (обратная совместимость).
* FR-1.6 Валидация параметров: `temperature` ∈ [0, 2], `top_p` ∈ (0, 1],
  `num_predict` ∈ [1, 32768], `num_ctx` ∈ [512, 1048576], `seed` —
  целое. Ошибки — `ValueError` с русским текстом.

### FR-2 Context window (`num_ctx`)

* FR-2.1 Если профиль задаёт `num_ctx`, запрос к модели идёт
  **нативным** `POST {OLLAMA_BASE_URL без /v1}/api/chat` с
  `options.num_ctx`, потому что OpenAI-совместимый
  `/v1/chat/completions` этот параметр игнорирует (проверено на
  Ollama 0.34.4: `ollama ps` показывает авто-`CONTEXT 32768`).
* FR-2.2 Если `num_ctx` не задан, запрос идёт прежним
  OpenAI-совместимым путём без `num_ctx` (регрессия дней 11–28).
* FR-2.3 Фактический context window загруженной модели равен
  `num_ctx` профиля (проверяется через `GET /api/ps`).

### FR-3 Prompt-шаблон под кейс

* FR-3.1 `SERIES_SYSTEM_PROMPT` содержит: роль (эксперт по сериалам),
  жёсткое правило «рекомендуй ТОЛЬКО из каталога, используй ровно те
  id», требование вернуть пустой список, если ничего не подошло,
  формат JSON и few-shot пример.
* FR-3.2 Пользовательское сообщение содержит запрос и
  пронумерованный каталог кандидатов (`[n] Название — год — жанры —
  страна — IMDb`).
* FR-3.3 Название/год/жанры/страна рекомендации подставляются **из
  каталога** по `id`, а не берутся из ответа модели: выдуманное
  название невозможно.

### FR-4 Разбор ответа

* FR-4.1 `extract_json` извлекает JSON из чистого ответа,
  ```json-обёртки или текста вокруг сбалансированного объекта/массива;
  корректно обрабатывает строки и экранирование.
* FR-4.2 `parse_series_answer` никогда не бросает исключение:
  неразобранный ответ → `parsed=False`, `picks=[]`.
* FR-4.3 Ответы `{"picks": [...]}`, голой массив и одиночный объект
  рекомендации — валидны.

### FR-5 Отбор кандидатов

* FR-5.1 Отбор детерминирован и НЕ использует LLM: одинаковый запрос
  и каталог → одинаковый список кандидатов у всех профилей.
* FR-5.2 Ограничения запроса вытаскиваются из текста: жанр (с
  алиасами), страна (включая прилагательные «российск/британск/
  корейск»), год («после N» → N+1, «не старше N», «N года или новее»,
  «ровно N года»).
* FR-5.3 Среди кандидатов есть записи, НЕ удовлетворяющие
  ограничениям (иначе задача выбора тривиальна и метрика
  соблюдения ограничений ничего не измеряет).

### FR-6 Метрики

* FR-6.1 По каждому поиску возвращаются: `latency_sec`,
  `prompt_tokens`, `completion_tokens`, `tokens_per_sec`, `num_ctx`,
  `parsed`, `hallucination_rate`, `constraint_satisfaction`.
* FR-6.2 `hallucination_rate` = доля рекомендованных `id` вне
  предложенного каталога.
* FR-6.3 `constraint_satisfaction` = доля рекомендаций,
  удовлетворяющих всем ограничениям запроса.
* FR-6.4 `POST /api/series/compare` сравнивает профили на наборе
  запросов; падение отдельного запроса не прерывает сравнение (в
  строке остаётся `error`).

### FR-7 Каталог

* FR-7.1 Каталог загружается из `data/series/catalog.json`; битый или
  отсутствующий файл → пустой список (не исключение).
* FR-7.2 `GET /api/series/catalog` отдаёт статистику (всего, годы,
  жанры, страны) и образец записей; пустой каталог — `ready: false`,
  не ошибка.

### FR-8 REST

| Метод | Путь | Ответ | Ошибки |
|---|---|---|---|
| GET | `/api/tuning/profiles` | `{active, profiles[]}` | — |
| POST | `/api/tuning/profile` | `{active}` | 400 неизвестный/пустой профиль |
| GET | `/api/tuning/report` | отчёт замеров | — |
| GET | `/api/series/catalog` | `{stats, sample, ready}` | — |
| POST | `/api/series/search` | рекомендации + метрики | 400 запрос/limit/профиль; 502 каталог/Ollama |
| POST | `/api/series/compare` | `{profiles, rows}` | 400 пустой/битый список, неизвестный профиль |

* FR-8.1 `limit` ∈ [1, 10] (bool отвергается).
* FR-8.2 Активный профиль хранится в `studio/data/tuning.json`, а НЕ в
  `config.json`: контракт `POST /api/config` дней 11–28 не меняется.

### FR-9 UI

* FR-9.1 Вкладка «Сериалы» открывается кнопкой 🎬 в шапке чата.
* FR-9.2 Показывает параметры активного профиля (`temperature`,
  max tokens, context window, seed, JSON-режим) и промпт-шаблон по
  кнопке.
* FR-9.3 Показывает статистику каталога, поле запроса, подсказки,
  карточки рекомендаций (название, год, жанры, страна, «почему
  подходит») и метрики ответа.
* FR-9.4 Показывает сравнение профилей.

## Нефункциональные требования

* NFR-1 Новых зависимостей нет (stdlib + уже имеющиеся fastapi/httpx).
* NFR-2 Профиль `studio` и OpenAI-совместимый путь сохраняют
  поведение дней 11–28 бит-в-бит (регрессия).
* NFR-3 Оптимизация — только инференс (параметры, квант, промпт);
  fine-tuning вне scope.
* NFR-4 Замеры квантования контролируемые: одинаковые промпты и
  кандидаты, фиксированный `seed`, одинаковые `num_ctx` и
  `num_predict`.

## Критерии приёмки

* AC-1 `pytest -q -m "not live"` → 0 failed.
* AC-2 `npx tsc -b` → exit 0; `vitest run` → 0 failed.
* AC-3 `e2e_day29.py` → Part A 8/8 PASS; Part B без FAIL.
* AC-4 Live: `ollama ps` показывает `CONTEXT`, равный `num_ctx`
  профиля (8192), а не авто-дефолт.
* AC-5 Live: на золотом наборе `format_validity` ≥ 90 %,
  `hallucination_rate` ≤ 5 %.
* AC-6 Цифры до/после (профиль `studio` против `series`) в отчёте и
  документации.
