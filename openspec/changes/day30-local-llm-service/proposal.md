# Proposal: day30-local-llm-service

## Why

День 30: **развернуть локальную LLM как приватный сервис**, к которому
можно подключиться с любого устройства по локальной сети, с
ограничениями по **rate limit** и **max context**.

К дню 30 в репозитории уже есть:

* локальная LLM (день 26: Ollama как второй провайдер, `LOCAL_MODELS`,
  `_base_for()`, динамическое обнаружение моделей);
* полностью локальный RAG (день 28: эмбеддер `nomic-embed-text:v1.5`);
* профили инференса с `num_ctx` (день 29: `tuning.py`, `TaskProfile`).

Но всё это — **внутренности Студии**. Ollama слушает `127.0.0.1:11434`
и не имеет ни авторизации, ни лимитов, ни учёта. Подключиться к ней
«с любого устройства по сети» сейчас нельзя, а если открыть её в LAN
напрямую — получится **открытый наружу инференс без ограничений**:
любой в сети жжёт GPU, любой размер контекста съедает память, и никто
не знает, кто сколько потратил.

День 30 закрывает этот разрыв: между клиентами и Ollama встаёт
**шлюз** (`studio/backend/gateway.py`) — OpenAI-совместимый
`/v1/chat/completions`, который:

1. **Слушает LAN** (`0.0.0.0`) и принимает запросы от любых устройств
   (ноутбук, телефон, планшет) — с любого OpenAI-клиента, без правок
   на стороне клиента;
2. **Требует API-ключ** клиента — анонимных запросов нет;
3. **Ограничивает rate limit** — RPM/TPM на клиента, скользящее окно;
4. **Ограничивает контекст** — на запрос и на клиента, с
   **автоматической компрессией**: при упоре в лимит старые ходы
   сжимаются LLM-сводкой, а не отбрасываются молча и не роняют запрос
   в 400;
5. **Считает использование** — токены, запросы, отказы по каждому
   клиенту, видно в UI.

### Ключевое решение: компрессия вместо отказа

Задание допускает трактовать «max context» как жёсткий отказ. Но
жёсткий отказ делает сервис бесполезным ровно тогда, когда он нужен:
длинный диалог с телефона упирается в лимит и клиент получает 400 без
объяснения. Поэтому лимит контекста — **не стена, а триггер
компрессии**:

* вход укладывается в лимит → запрос идёт как есть (нулевые накладные);
* вход превышает лимит → старые ходы сжимаются **LLM-сводкой**
  (локальная модель, тот же Ollama), system-промпт и последние ходы
  сохраняются целиком;
* после компрессии всё ещё не влезает → отказ с явным кодом и
  подсказкой, сколько именно просили (не молчаливая обрезка).

Компрессия видна клиенту: в ответе есть `x-gateway-compressed` и
блок `gateway` с числом сжатых сообщений и токенов до/после — то есть
поведение сервиса наблюдаемо, а не магическое.

### Что НЕ делаем (осознанно)

* **TLS не поднимаем** — согласованный скоуп: сервис работает
  **только внутри локальной сети**, наружу не выставляется. Ключи по
  HTTP в доверенном LAN — принятый компромисс; в документации явно
  написано, что наружу так выпускать нельзя.
* **Не отдельный микросервис** — шлюз живёт в том же FastAPI-процессе
  Студии: переиспользует `tuning.py` (профили, `num_ctx`), `agent.py`
  (маршрутизация на Ollama) и уже принятый в репозитории паттерн e2e.

## What Changes

### Новый модуль `studio/backend/gateway.py`
- `GatewayClient` (dataclass): `name`, `key` (хэш), `rpm`, `tpm`,
  `max_context`, `enabled`, `daily_quota`, `allow_models`.
- `GatewayConfig`: загрузка/сохранение клиентов (`gateway.json`),
  дефолт из `.env` (`GATEWAY_CLIENTS`), hot-reload без рестарта.
- `RateLimiter`: скользящее окно (RPM/TPM) на клиента, потокобезопасно.
- `compress_messages()`: LLM-сводка старых ходов при упоре в
  `max_context` — сохраняет system + последние N ходов, сводка
  инжектится как system-сообщение.
- `UsageStore`: счётчики запросов/токенов/отказов на клиента,
  персистентно, кольцевой лог последних отказов.
- `GatewayService.handle_chat()`: полный конвейер (аутентификация →
  лимиты → контекст → компрессия → прокси в Ollama → учёт).
- Ошибки в формате OpenAI (`{"error": {"message", "type", "code"}}`),
  коды: 401 / 403 / 404 / 413 / 429 / 502.

### Роуты в `studio/backend/main.py`
- `POST /v1/chat/completions` — OpenAI-совместимый (stream и не-stream);
- `GET /v1/models` — список доступных моделей;
- `GET /api/gateway/status` — состояние сервиса + адрес в LAN;
- `GET /api/gateway/clients` / `POST` / `DELETE` — CRUD клиентов;
- `GET /api/gateway/usage` — использование по клиентам;
- `GET /api/gateway/rejections` — лог отклонённых запросов.

### UI: вкладка «Сервис»
- адрес для подключения с других устройств (LAN IP + порт),
  готовый `curl`/Python-сниппет;
- таблица клиентов: ключ (маскирован), RPM/TPM/контекст, вкл/выкл;
- живой счётчик использования (запросы, токены, отказы);
- лог отклонённых запросов с причиной.

### Скрипты и тесты
- `studio/backend/tests/test_gateway.py` — офлайн-тесты (TDD);
- `scripts/e2e_day30.py` — Part A офлайн (TestClient) + Part B live
  (реальный сервер в LAN + реальный Ollama).
