# Spec: cli-md-agents

## Назначение

Терминальный вход в ассистента (`studio/cli.py`) поверх того же
`AssistantService`, что использует HTTP-API, и определения агентов в
формате Markdown (`agents/*.md`) для двух исполнений — API и CLI.

## Термины

* **Агент** (`AgentSpec`) — определение в `agents/*.md`: метаданные
  (frontmatter) + системный промпт (тело).
* **Исполнение** (`execution`) — `api` (HTTP/Студия) или `cli`
  (терминал); определяет форму вывода и канал.
* **Реестр** (`AgentRegistry`) — загрузка и выборка агентов из каталога
  `agents/`, кэш по mtime.

## Функциональные требования

### FR-1 Определения агентов в Markdown

* FR-1.1 Система SHALL хранить определения агентов в `agents/*.md` с
  frontmatter-блоком, ограниченным `---`.
* FR-1.2 Frontmatter SHALL поддерживать поля `name`, `execution`,
  `description`, `tools`, `temperature`.
* FR-1.3 Обязательные поля: `name`, `execution`, `description`;
  тело агента MUST быть непустым.
* FR-1.4 `execution` SHALL принимать только `api` или `cli`.
* FR-1.5 Система SHALL предоставлять **4 агента × 2 исполнения = 8
  файлов**: `project-qa`, `code-review`, `support`, `file-ops` — каждый
  в `.api.md` и `.cli.md`.
* FR-1.6 Отсутствие `tools` SHALL означать пустой список; отсутствие
  `temperature` — значение по умолчанию.
* FR-1.7 Некорректный frontmatter (нет `---`, битая строка, неизвестное
  `execution`, пустое тело) MUST приводить к ошибке с указанием файла и
  причины, а не к молчаливому пропуску.

### FR-2 Реестр агентов

* FR-2.1 `AgentRegistry` SHALL загружать все `agents/*.md` каталога.
* FR-2.2 `list()` SHALL возвращать агентов с метаданными, доступными
  для отображения (без тела промпта).
* FR-2.3 `get(name, execution)` SHALL возвращать точное совпадение
  `<name>.<execution>.md`.
* FR-2.4 Если файла запрошенного исполнения нет, система SHALL
  деградировать на другое исполнение того же агента и **явно помечать**
  это (`fallback: true`).
* FR-2.5 Неизвестный агент MUST приводить к ошибке со списком
  доступных.
* FR-2.6 Правка md-файла SHALL подхватываться без перезапуска процесса
  (кэш инвалидируется по mtime).
* FR-2.7 Недоступный/пустой каталог `agents/` MUST NOT ронять CLI:
  возвращается пустой список или ошибка с RU-текстом.

### FR-3 CLI: состав команд

* FR-3.1 `agents list` — список агентов (имя, исполнение, описание).
* FR-3.2 `agents show <name> [--execution E]` — метаданные агента.
* FR-3.3 `ask <вопрос> [--agent N] [--top-k K]` — вопрос по проекту
  (RAG), вывод с источниками.
* FR-3.4 `review [--diff FILE] [--base BRANCH] [--out FILE]` — ревью
  изменений с находками по severity.
* FR-3.5 `tickets [--status S] [--priority P] [--topic T]` — список
  тикетов CRM.
* FR-3.6 `support <TICKET_ID> [--question Q]` — ответ по тикету с
  блоком применённых данных CRM.
* FR-3.7 `scenario <name> [--param k=v]...` — запуск сценария, вывод
  сводки, изменённых файлов и diff.
* FR-3.8 `scenarios` — каталог сценариев.
* FR-3.9 `index [--strategy S]` — сборка индекса проекта.
* FR-3.10 `status` — состояние (индекс, корпус, CRM, LLM, git).
* FR-3.11 `git` — ветка, изменённые файлы, diff.

### FR-4 CLI: поведение

* FR-4.1 CLI SHALL переиспользовать `AssistantService` и MUST NOT
  дублировать логику RAG, ревью, CRM или сценариев.
* FR-4.2 CLI MUST NOT выполнять git-мутации.
* FR-4.3 Вывод по умолчанию — markdown в stdout.
* FR-4.4 Флаг `--json` SHALL давать машинный вывод.
* FR-4.5 Флаг `--out FILE` SHALL записывать вывод в файл
  (`review`, `scenario`).
* FR-4.6 Код возврата: `0` — успех, `1` — ошибка.
* FR-4.7 Ошибки SHALL выводиться в stderr с RU-текстом; traceback
  только при `--debug`.
* FR-4.8 Значения `--param` SHALL типизироваться: `true/false`,
  `none`, числа и строки — иначе `dry_run=false` (непустая строка)
  трактуется как истина и **записывает файлы** вместо dry-run.
* FR-4.9 CLI SHALL работать без запущенного HTTP-сервера.
* FR-4.10 Неизвестная подкоманда/аргумент MUST приводить к понятной
  ошибке и коду 1 (или 2 для ошибки разбора argparse), а не к traceback.

### FR-5 Выбор агента

* FR-5.1 `--agent NAME` SHALL задавать агента для `ask`, `review`,
  `support`, `scenario`.
* FR-5.2 Без `--agent` SHALL использоваться агент по умолчанию для
  команды (`project-qa` для ask, `code-review` для review, `support`
  для support, `file-ops` для scenario).
* FR-5.3 Системный промпт выбранного агента SHALL передаваться в вызов
  LLM.

### FR-6 Тесты и проверка

* FR-6.1 Парсер и реестр SHALL покрываться офлайн-тестами.
* FR-6.2 Подкоманды SHALL покрываться тестами через `main(argv)` без
  сети.
* FR-6.3 `scripts/e2e_day32.py` SHALL проверять CLI как **реальный
  подпроцесс** (не вызов функции): Part A офлайн, Part B live.

## Нефункциональные требования

* NFR-1 Только stdlib + уже используемые зависимости; новых пакетов
  не требуется (frontmatter парсится без PyYAML).
* NFR-2 Существующие модули дней 11–34 не изменяются.
* NFR-3 `agents.py` и `cli.py` импортируются без побочных эффектов:
  сеть и диск при импорте не трогаются.
* NFR-4 Все сообщения об ошибках — на русском языке.
* NFR-5 CLI запускается как `python -m studio.cli` и из
  `studio/backend` (flat-режим), как остальные скрипты репозитория.
